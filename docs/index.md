# MCP-сервер

MCP-сервер даёт агенту VS Code, Cursor или Claude Code доступ к командам расширения 1C: Platform Tools: тесты, профили запуска, сборка и загрузка конфигурации и расширений, работа с базой. Агент вызывает ровно те же команды, что вы нажимаете кнопками. Сервер живёт отдельным расширением **1C: Platform Tools MCP** и общается с 1C: Platform Tools по локальному каналу.

## Установка

1. Установите **1C: Platform Tools**: [Marketplace](https://marketplace.visualstudio.com/items?itemName=yellow-hammer.1c-platform-tools), [Open VSX](https://open-vsx.org/extension/yellow-hammer/1c-platform-tools).
2. Установите **1C: Platform Tools MCP**: [Marketplace](https://marketplace.visualstudio.com/items?itemName=yellow-hammer.mcp-1c-platform-tools), [Open VSX](https://open-vsx.org/extension/yellow-hammer/mcp-1c-platform-tools).
3. Откройте проект 1С: папку с `packagedef`.

## Подключение

Агент работает с тем окном VS Code или Cursor, из которого запущен. Каждое окно 1C: Platform Tools открывает свой канал и записывает в реестр окон, какие папки и проекты оно обслуживает, а MCP-сервер находит окно в этом реестре. Порт, токен и включение канала не настраиваются: так в VS Code, Cursor и Claude Code.

**VS Code** больше ничего не требует: расширение регистрирует MCP-сервер само и передаёт ему окно, из которого он запущен.

**Cursor** не поддерживает провайдер MCP-серверов VS Code, поэтому сервер подключается через `.cursor/mcp.json` проекта. Файл создаёт и обновляет расширение:

1. Палитра команд → **1C: Platform Tools MCP: Настроить MCP для Cursor**, либо дерево **1С: Инструменты** → **Навыки для AI** → **Настроить MCP для Cursor**.
2. Перезагрузите окно.
3. Включите сервер `mcp-1c-platform-tools` в настройках MCP: новый сервер Cursor добавляет выключенным.

**Claude Code** берёт сервер из `.mcp.json` проекта. Файл пишет команда **1C: Platform Tools MCP: Настроить MCP для Claude Code** или пункт **Навыки для AI** → **Настроить MCP для Claude Code**, сценарий работы — в разделе [Claude Code](#claude-code).

Команды пишут путь к серверу и папку проекта, по которой сервер находит окно, и сохраняют другие серверы файла. Путь содержит версию расширения, поэтому после обновления запись устаревает и сервер падает с `MODULE_NOT_FOUND`; расширение чинит это при запуске, если запись ведёт на другую установку этого же расширения. Запись с путём, прописанным вручную, остаётся как есть.

### Настройка вручную

Если конфиг заводится без расширения, укажите путь к серверу и папку проекта, открытую в VS Code или Cursor:

```json
{
  "mcpServers": {
    "mcp-1c-platform-tools": {
      "command": "node",
      "args": ["<каталог расширения>/out/src/index.js"],
      "env": {
        "MCP_1C_WORKSPACE": "<папка проекта>"
      }
    }
  }
}
```

Каталог расширения: `%USERPROFILE%\.cursor\extensions\yellow-hammer.mcp-1c-platform-tools-<версия>-universal` (Windows) или `~/.cursor/extensions/...` (macOS, Linux); после обновления расширения такой путь придётся поправить руками. Без `MCP_1C_WORKSPACE`, например в глобальном `%USERPROFILE%\.cursor\mcp.json`, окно выбирается по каталогу, из которого клиент запустил сервер, а если он не в папке окна — по `projectPath` вызова.

## Claude Code

Команды 1С выполняет расширение в окне, поэтому Claude Code работает с проектом через окно VS Code или Cursor:

1. Один раз запишите `.mcp.json` проекта командой **Настроить MCP для Claude Code**.
2. Откройте проект в VS Code или Cursor. Агент может сделать это сам: `code <путь>` или `cursor <путь>`.
3. Запустите Claude Code в папке проекта: сервер найдёт окно этой папки, и агент вызывает команды без настройки связи.

Если окно открыто позже, чем запущен Claude Code, у сервера будет только инструмент `onec_platform_tools_status`. Агент вызывает его, когда окно загрузится, и инструменты появляются.

## Несколько окон

Окна друг другу не мешают: у каждого свой канал, и агент работает с окном, из которого запущен.

- Проект другого окна окно агента не выполняет: приходит отказ `WORKSPACE_MISMATCH` с именем окна, в котором проект открыт. Продолжайте с агентом того окна.
- Агенту вне окон, например Claude Code в общем каталоге проектов, окно выбирается по `projectPath`. Проект не открыт ни в одном окне — приходит `WINDOW_NOT_FOUND`.
- Папка, открытая в двух окнах, даёт отказ `WINDOW_AMBIGUOUS`: оставьте её в одном окне.

Коды отказов и что с ними делать — в [параметрах инструментов](tool-parameters.md#окно-агента).

## Проекты окна

В окне бывает несколько проектов — каталогов с `packagedef`: папки рабочей области, подпроекты и проекты внутри папок. В окне из нескольких папок (`.code-workspace`) годится проект из любой папки окна. Команды без `projectPath` выполняются в текущем проекте окна, а пока пользователь его не выбрал — в проекте из настройки `1c-platform-tools.project.default`. `project_list` показывает проекты окна, `project_select` переключает текущий, `projectPath` направляет один вызов в другой проект этого окна.

## Где работает сервер и чем защищён канал

Реестр окон лежит в домашнем каталоге пользователя, `~/.1c-platform-tools/windows`, на машине, где работает хост расширений. В Remote, WSL и Codespaces это удалённая машина, и MCP-сервер должен работать там же. VS Code запускает его там сам; записи `.cursor/mcp.json` и `.mcp.json` тоже ведут к серверу на удалённой машине.

Канал окна — именованный канал Windows или Unix-сокет со случайным именем. Запросы по нему выполняются только с токеном окна, а токен лежит в записи окна в реестре. На Linux и macOS сокет и реестр к тому же лежат в каталогах, закрытых от других пользователей; при длинном `TMPDIR` сокет создаётся в `/tmp`, чтобы путь уложился в предел длины.

В недоверенной папке окно канал не открывает и в реестр не попадает: агент с ним не работает.

## Проверка

Напишите агенту «покажи состояние окружения 1С». В ответе будут активный профиль запуска, версия платформы и путь к базе. Дальше можно просить прогон тестов, переключение профиля, сборку конфигурации.

## Как агент работает с командами

- **Агент дожидается результата.** Инструменты возвращают код возврата и вывод команды, у прогонов тестов ещё и счётчики из отчёта. С параметром `wait: false` команда уходит в терминал, и ход выполнения видно на экране.
- **Окна не открываются.** Команда, вызванная агентом, никогда не показывает окна выбора: если данных не хватает, возвращается ошибка с подсказкой, какие параметры передать. Интерактивные мастера (поставка, установка версии, создание профиля) агенту недоступны, их выполняет пользователь.
- **Профиль и окружение.** `env_status` показывает активный профиль, файл настроек, строку подключения, выбранное окружение и имена его переменных; `env_selectProfile` и `env_selectEnvironment` переключают профиль и окружение по имени. Разовый прогон под другим файлом настроек задаётся параметром `settingsFile`: активный профиль при этом не меняется, а параметры вызова имеют приоритет над временными параметрами профиля.
- **Ошибки видны как ошибки.** Упавшие тесты, ошибки синтаксического контроля, ненулевой код возврата и обрыв связи с расширением помечают ответ как неуспешный. Синтаксический контроль отдаёт список ошибок с путём к файлу модуля. Длинный вывод обрезается до хвоста, целиком он остаётся в панели расширения.
- **Исходный код находится сам.** Каталоги исходного кода инструменты не принимают: конфигурацию, расширения, внешние обработки и отчёты расширение находит в проекте, в выгрузке конфигуратора и в проектах 1С:EDT.
- **Проекты окна.** Команды без `projectPath` выполняются в текущем проекте окна, `projectPath` направляет один вызов в другой проект, не меняя текущий. `project_init` делает проектом каталог без `packagedef`.

## Автоматизация из агента

Агенту доступна команда `pipelines_run` с параметром `pipeline`: идентификатор или название цепочки из `.1cpt/pipelines.json`. `profile` и `environment` задают профиль и окружение на этот прогон вместо выбранных в редакторе; шаги со своими в пайплайне их сохраняют. Возвращается пошаговый отчёт: что выполнено, что упало, сколько попыток.

Редакторы пайплайнов и хуков агенту не публикуются: файлы он правит напрямую, состав полей подсказывают схемы `pipelines.schema.json` и `hooks.schema.json`. Шаг с подтверждением в таком запуске завершается ошибкой: подтверждать некому.
